# ssh-conn

![ssh-conn](Assets/ssh-conn-brand/banner/svg/banner-social-dark.svg)

Консольная утилита для быстрого подключения к SSH-серверам: все параметры
подключений хранятся в одном файле, а подключение выполняется по короткому имени.

```bash
$ ssh-conn list
Имя хоста | Адрес         | Порт | Пользователь | Ключ
----------+---------------+------+--------------+------------------
prod      | 203.0.113.10  | 22   | root         | ~/.ssh/id_ed25519
stage     | 203.0.113.20  | 2222 | deploy       | ~/.ssh/stage_key

$ ssh-conn prod
# сразу открывается ssh-сессия root@203.0.113.10
```

## Возможности

- `list` — таблица всех серверов;
- графический интерфейс `ssh-conn-gui` — группы хостов в боковой панели,
  таблица с поиском, добавление, правка и удаление записей, подключение в Terminal;
- подключение по имени сервера;
- `add` / `edit` / `remove` — управление записями, в том числе интерактивно;
- порт по умолчанию (22) для записей без поля `Port`;
- сохранение комментариев и незнакомых ключей в файле конфигурации при правках.

## Установка

Требуется macOS 14+ и Swift 6.4+.

### CLI

Для сборки CLI достаточно Command Line Tools:

```bash
swift build -c release --product ssh-conn
install -m 755 .build/release/ssh-conn /usr/local/bin/ssh-conn
```

Без установки можно запускать через SwiftPM: `swift run ssh-conn list`.

### GUI

Для сборки графического интерфейса нужен установленный Xcode: начиная с SDK
macOS 26 SwiftUI использует макросы, плагины которых не входят в Command Line
Tools. Если Xcode установлен в нестандартном месте, укажите его через
`DEVELOPER_DIR`.

```bash
# запуск из исходников
swift run ssh-conn-gui

# сборка приложения build/ssh-conn.app
Scripts/build-app.sh
open build/ssh-conn.app
```

### Дистрибутив (DMG)

```bash
Scripts/build-dmg.sh          # build/ssh-conn-1.0.dmg
open build/ssh-conn-1.0.dmg
```

Скрипт собирает приложение, проверяет подпись и создаёт сжатый образ с
`ssh-conn.app` и ярлыком `Applications`; контрольная сумма и содержимое образа
проверяются автоматически. Аргумент `debug`/`release` выбирает конфигурацию
(по умолчанию `release`).

По умолчанию приложение подписано ad-hoc, поэтому на другом Mac Gatekeeper
предупредит о неизвестном разработчике. Для распространения подпишите
приложение сертификатом Developer ID и нотаризуйте образ (нужен Xcode с
`notarytool`):

```bash
CODESIGN_IDENTITY="Developer ID Application: Имя (TEAMID)" \
NOTARIZE=1 APPLE_ID="you@example.com" TEAM_ID="TEAMID" \
NOTARY_PASSWORD="app-specific-password" \
Scripts/build-dmg.sh
```

## Конфигурация

По умолчанию используется `~/.ssh-conn.config`. Путь переопределяется
переменной окружения `SSH_CONN_CONFIG` — удобно для нескольких профилей
или для проверки на тестовой копии:

```bash
SSH_CONN_CONFIG=~/tmp/test.config ssh-conn list
```

Файл состоит из блоков «`Ключ значение`». Блоки разделяются пустой строкой,
строки, начинающиеся с `#`, считаются комментариями.

```
# продакшн
Name prod
Host 203.0.113.10
Port 22
User root
Key ~/.ssh/id_ed25519

Name stage
Group staging
Host 203.0.113.20
Port 2222
User deploy
Key ~/.ssh/stage_key
```

| Поле | Обязательное | Описание |
|---|---|---|
| `Name` | да | имя сервера для командной строки; с него начинается блок |
| `Host` | да | адрес хоста или IP |
| `Port` | нет | порт SSH, по умолчанию `22` |
| `User` | да | имя пользователя |
| `Key` | да | путь к приватному ключу |
| `Group` | нет | логическая группа; записи без поля попадают в «Без группы» |

Особенности разбора:

- записи без обязательных полей молча пропускаются и не попадают в `list`;
- порядок полей в блоке произвольный, незнакомые ключи игнорируются, но
  сохраняются при `edit`;
- `Group` необязателен и может содержать пробелы; поле сохраняется при правках,
  а пустое значение в GUI удаляет его из записи;
- `~` в пути к ключу разворачивается в домашний каталог, относительный путь
  отсчитывается от домашнего каталога;
- если файла нет, `list`, `edit` и `remove` сообщают об ошибке, а `add`
  создаёт его вместе с недостающими каталогами.

## Команды

```
ssh-conn <сервер>                — подключиться к серверу
ssh-conn list                    — показать список серверов
ssh-conn add <имя> [опции]       — добавить сервер
ssh-conn remove <имя> [--force]  — удалить сервер
ssh-conn edit <имя> [опции]      — изменить сервер
ssh-conn help                    — показать справку
```

Опции `add` и `edit`:

| Опция | Описание |
|---|---|
| `--host <адрес>` | адрес хоста |
| `--port <порт>` | порт SSH (1–65535, по умолчанию 22) |
| `--user <имя>` | имя пользователя |
| `--key <путь>` | путь к приватному ключу |
| `--group <имя>` | группа сервера; пустое значение (`--group=`) убирает группу |
| `--rename <имя>` | новое имя сервера (только `edit`) |
| `--force` | перезаписать существующую запись (`add`) или удалить без подтверждения (`remove`) |

Если хотя бы у одной записи задано поле `Group`, команда `list` добавляет
столбец «Группа» (конфиги без групп выводятся как раньше).

Значения можно передавать и как `--port=2222`. Если терминал доступен,
недостающие значения `add` и `edit` запрашивают интерактивно; без терминала
отсутствие обязательного поля — ошибка (удобно для скриптов). Если файл ключа
не существует, выводится предупреждение, но запись всё равно сохраняется.

## Графический интерфейс

`ssh-conn-gui` — приложение на SwiftUI, которое работает с тем же файлом
конфигурации (переменная `SSH_CONN_CONFIG` учитывается):

- боковая панель с группами и счётчиками, отдельными пунктами «Все хосты»
  и «Без группы»;
- таблица хостов с поиском по имени, адресу, группе и пользователю;
- добавление, изменение и удаление записей с проверкой полей и уникальности имени;
  в редакторе можно ввести новую группу или выбрать существующую, а новая запись
  подставляет группу, выбранную в боковой панели;
- подключение двойным кликом по строке или кнопкой в панели инструментов —
  SSH-сессия открывается в Terminal;
- обновление списка после внешних правок файла (вручную и при возврате в окно),
  путь к конфигу и кнопка «Показать в Finder» в строке состояния;
- предупреждение, если файл приватного ключа не найден, и выбор ключа через
  стандартный диалог.

При первом подключении macOS может запросить разрешение на управление Terminal
(приложение использует AppleScript). Если разрешение не выдано, открывается
временный `.command`-файл в Terminal; если и это не удалось, команда `ssh`
показывается в сообщении об ошибке.

## Примеры

```bash
# добавить сервер без интерактивных вопросов
ssh-conn add prod --host 203.0.113.10 --user root --key ~/.ssh/id_ed25519

# добавить интерактивно (спросит недостающие поля)
ssh-conn add stage

# сменить порт и пользователя
ssh-conn edit prod --port 2200 --user deploy

# добавить сервер в группу и затем убрать её
ssh-conn add db --host 203.0.113.30 --user postgres --key ~/.ssh/db_key --group "Базы"
ssh-conn edit db --group=

# переименовать запись
ssh-conn edit stage --rename staging

# перезаписать существующую запись целиком
ssh-conn add prod --host 203.0.113.11 --user root --key ~/.ssh/id_ed25519 --force

# удалить без подтверждения
ssh-conn remove staging --force
```

## Как это работает

Для подключения утилита формирует аргументы `ssh -i <ключ> -p <порт> user@host`
и заменяет свой процесс клиентом `ssh` (`execvp`), поэтому пароли, ключи с
парольной фразой, `~/.ssh/config`, агент и интерактивный ввод работают так же,
как при прямом вызове `ssh`. Бинарник `ssh` ищется по `PATH`.

## Структура проекта

```
Sources/
├── SSHConnCore/        # общая библиотека
│   ├── ServerConfig.swift  # модель записи, разбор блоков, путь к конфигу
│   ├── ConfigStore.swift   # чтение и правка файла конфигурации
│   └── SSH.swift           # запуск ssh из CLI
├── SSHConnCLI/         # консольная утилита
│   ├── main.swift          # точка входа и разбор команды
│   └── CLI.swift           # справка, разбор опций, команды, вывод таблицы
└── SSHConnGUI/         # приложение SwiftUI
    ├── SSHConnGUIApp.swift # точка входа приложения
    ├── HostListModel.swift # состояние списка и валидация записей
    ├── HostListView.swift  # окно со списком хостов
    ├── HostEditorView.swift # форма добавления и редактирования
    └── TerminalLauncher.swift # подключение через Terminal

Scripts/
├── build-app.sh        # сборка build/ssh-conn.app
└── build-dmg.sh        # упаковка приложения в build/ssh-conn-<версия>.dmg
```

Сборка: `swift build --product ssh-conn` для CLI и `Scripts/build-app.sh` для
приложения. Запуск из VS Code описан в `.vscode/launch.json` (конфигурации Debug
и Release для CLI и GUI). Автотестов пока нет.
